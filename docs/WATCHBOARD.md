# ETF 看盘台（Watchboard）V1 方案

## 0. 一页话

把《看盘三件套》的三层框架——**流动性（有没有钱）→ 量能（钱动没动）→ 宽基 ETF（大钱进没进）**
——做成一个本地、可复现、每一层都能追到原始出处的盘面看板：

```text
顶部：三层状态 + 共振结论（防守 / 中性观望 / 偏多 / 数据不足）
中部：三层各自的原始事实与派生指标（成交额、两融、量比、净申购、折溢价、位置分位）
底部：宽基 ETF 篮子明细，逐个标的的份额变化与折溢价，可下钻到 ETF 详情
```

它回答"市场现在处于什么状态、该用什么仓位表达"，**不回答**"明天涨跌"，也**不给**买卖建议。
这条边界与 `docs/PRODUCT.md` 第 8 节、`docs/ARCHITECTURE.md` 的 Fact / Derived / Opinion 分离一致。

### 1.3 口径纪律（不可破坏）

1. **单位统一**：库内成交额一律为**元**；上交所概况页给的是亿元，适配器负责换算，原始值进 `raw`。
2. **缺失即 NULL**：深交所不披露换手率 → `szse_turnover_rate_pct = NULL`，不用 0 顶替，也不用
   "成交额 ÷ 流通市值"冒充换手率（那是另一个指标，另起字段名）。
3. **口径必须写进表**：本方案的成交额口径是**沪深两市股票**，不含北交所、不含基金债券。
   字段名与文档里都要写清楚，禁止简写成"全市场"。
4. **派生 vs 事实**：成交额、两融余额、涨跌家数是**事实**（来自交易所/上游）；
   量比、均量、分位、三层状态是**派生**（进 `mart`，带 `calculation_version`）。
5. **规则不是观点**：三层判定是**确定性规则引擎**（当前 `pulse_v2`），规则写死在代码里、
   带版本号、有单测；它产出的是"状态标签"，不是"看多/看空观点"。
   `docs/ARCHITECTURE.md` 第 6 节的 Opinion（AI 解释）仍然只能进 `analysis.*`。

## 2. 三层判定规则（`pulse_v2`）

### 2.0 版本沿革与确认机制

```text
pulse_v1  2026-09-12  初版：三层各自打分 → 状态；三层共振 → 结论
pulse_v2  2026-09-12  加确认机制：某层原始信号必须连续 2 个交易日落在新状态才切换
```

为什么升 v2：v1 上线后把历史回放出来做状态热力图，才发现**状态机抖得太厉害**——

```text
            v1 切换次数 / 250 个交易日   平均每次持续
流动性              30 次                 8.1 天
量能                77 次                 3.2 天   ← 噪音
宽基 ETF            10 次                22.7 天
综合结论            69 次                 3.6 天   ← 失去"状态"的意义
```

根因是阈值偏紧（量比 ±10%、分位 0.4/0.6、两融 5 日 ±0.5%），日频数据在阈值附近
来回穿。修法不是放宽阈值（治标），而是**加确认**：原始信号连续
``CONFIRM_DAYS=2`` 天落在新状态才真的切过去，代价是滞后 1 天。

```text
            v1 → v2 切换次数
流动性        30 → 21
量能          77 → 35
宽基 ETF      10 → 5
综合结论      69 → 36      （平均状态持续 3.6 → 7 天）
```

原始信号与确认状态**都落库**：`*_raw_state` 与 `*_state` 不一致的那一天，
就是文档最看重的"**边际变化刚出现、还没被确认**"。

`UNKNOWN`（数据缺失）不参与确认、立即生效——数据开始覆盖或中断是口径事件，
不是市场状态。

三层各自从事实算出 `STRONG / NEUTRAL / WEAK / UNKNOWN`，每层 1 个子分项给 1 分。

### 第一层 · 流动性（有没有钱）

| 子信号 | 规则 | 依赖 |
| --- | --- | --- |
| 两融余额 5 日变化率 | `> +0.5%` → +1；`< -0.5%` → −1；否则 0 | `core.margin_balance_daily` |
| 两融余额 250 日分位 | `≥ 0.6` → +1；`≤ 0.4` → −1；否则 0 | 同上 |

合计 ≥ +1 → `STRONG`；= 0 → `NEUTRAL`；≤ −1 → `WEAK`；任一输入缺失 → `UNKNOWN`。

> 文档的核心法则是"看边际变化，不看绝对水平"。所以主信号是 5 日变化率，
> 250 日分位只作为位置参照，不单独下结论。

### 第二层 · 量能（钱动没动）

| 子信号 | 规则 | 依赖 |
| --- | --- | --- |
| 成交额量比（当日 ÷ 前 5 日均值） | `≥ 1.1` → +1；`≤ 0.9` → −1；否则 0 | `core.market_turnover_daily` |
| 20 日均额在过去 250 日中的分位 | `≥ 0.6` → +1；`≤ 0.4` → −1；否则 0 | 同上 |

状态映射同第一层。此外输出**量价四象限标签**（文档 2.4）：

```text
位置（宽基指数 250 日分位）× 量能方向（量比）
低位 + 放量 → 吸筹/启动      高位 + 放量 → 出货/赶顶（警戒）
低位 + 缩量 → 阴跌/筑底      高位 + 缩量 → 惜售或背离（谨慎）
```

四象限是**标签**，参与展示，不参与打分——避免把主观框架混进分数。

### 第三层 · 宽基 ETF（大钱进没进）

篮子定义（事实口径，不做名称模糊匹配）：

```text
跟踪指数 ∈ {000016 上证50, 000300 沪深300, 000510 中证A500,
            000905 中证500, 000852 中证1000, 000688 科创50, 399006 创业板指}
```

| 子信号 | 规则 | 依赖 |
| --- | --- | --- |
| 篮子 5 日估算净申购合计 | `> 0` → +1；`< 0` → −1 | `mart.etf_flow_daily` |
| 篮子 20 日估算净申购合计 | `> 0` → +1；`< 0` → −1 | 同上 |

折溢价、指数位置分位**只展示不打分**：文档自己就说"持续大幅溢价 = 过热（警惕）、
持续折价 = 抛压重（可能见底）"，方向不稳定，塞进分数会制造虚假精度。

### 总状态

```text
已知层数 < 2 → 数据不足（不给结论）
否则按文档 4.2：达成 STRONG 的层数 ≥ 2 → 偏多；= 1 → 中性观望；= 0 → 防守
```

每层同时输出 `note`（人话解释）和 `coverage`（该层数据覆盖到什么程度），
**覆盖不足必须显示出来**，不允许用一句"偏多"掩盖只有 8 只 ETF 的篮子。

> 上面的数字是 2026-09-12 用本机真实数据跑出来的（规则版本 `pulse_v2`），
> 不是示意值：那一天的结论就是"三层都偏弱 → 防守"。

设计原则：

- **数字永远带口径**：每个指标 hover 显示来源、as-of 日期、是否派生；
- **颜色只表达状态，不表达涨跌**（避免与"红涨绿跌"混淆）；
- **缺数据就留空并写明原因**，与现有研究台一致（"不会用示例行情代替事实"）；
- **事实与派生分区**：顶部是派生状态，中部是事实，底部是明细。

已实现的交互（2026-09-12）：

| 交互 | 说明 |
| --- | --- |
| 数据新鲜度条 | 每块数据（成交额/两融/份额/净值/快照/估值/状态）显示 as-of 与**滞后几个交易日**；两融通常滞后 1 个交易日，这是上游节奏，不是故障，但仍要上屏 |
| 成交额图窗口切换 | 60 / 120 / 250 个交易日，只切显示窗口，不改数据 |
| 成交额图悬停 | 显示当日成交额、20 日均额、沪市换手率 |
| 量价四象限散点 | 每个点是一天：横轴为沪深300 当日位置分位（250 日窗口），纵轴为当日量比；四象限底图用文档 2.4 的阈值（0.35/0.65 与 0.9/1.1），当前点高亮；悬停看当天明细 |
| 篮子表排序 | 点表头排序；NULL 永远排最后，不参与大小比较 |
| 篮子表分组 | 按跟踪指数筛选（全部 / 沪深300 / 中证A500 / 中证500 / 创业板指 …），带成员数 |
| 篮子表下钻 | 点任意一行打开抽屉，读该 ETF 的核心指标（规模、净申购、折溢价、均额、收益、回撤、跟踪误差、Top10 集中度）与缺失去因 |
| 三层状态历史热力图 | 4 行（流动性 / 量能 / 宽基 ETF / 综合结论）× 每个交易日一格，按状态着色；30/60/120/250 日窗口切换；悬停看当天该层的判定理由 |
| 边际变化标记行 | 热力图顶部一行：实心黑=结论切换、灰=单层变化、空心橙=原始信号已变但待确认 |
| 状态切换事件列表 | 最近的切换事件：日期、结论 from→to（或"结论不变"）、**领变层**、意义归类（资金先行信号 / 量能确认·背离 / 大钱动作 / 多层共振转向）与当天原始理由 |
| 待确认徽标 | 某层当日原始信号与确认状态不一致时，卡片上直接标"原始信号转 X，待确认"——这是最值得先看的一格 |
| 资金 vs 量能归一化对比 | 两融余额与成交额量纲不同，各自以窗口首日为 100 归一化后同轴对比；看"钱先来、量后到"的传导是否成立（实测：两融 115.6 vs 成交额 57.3，资金在进、量在缩） |
| 新发基金月度规模 | 按**成立日期**聚合的月度募集份额柱状图 + 近 3 个完整月 vs 前 3 个月的环比；当前月未录完不计入 |
| 篮子净申购累积曲线 | 按跟踪指数画累积净申购（窗口 2026-07-20 起），配"有日度数据的成员 n/m 只"覆盖率与近 5 日；缺失日不补 0、不插值 |

单位纪律（踩过坑，写在代码注释里）：折溢价是**比例**（0.0015 = +0.15%）、
涨跌幅是**百分数**（-1.69 = -1.69%）、换手率是**水平值**（不加正负号）。
三者不能共用同一个格式化函数——前端渲染回归测试专门盯这一点。

### 3.1 状态历史是"回放"，不是"当时的快照"

`mart.market_pulse_daily` 每天自然只会多一行，所以热力图刚上线时只有 1 格。
真正可用的做法是用**同一套 `pulse_v2` 规则在历史每一天上重算**：

```text
etf backfill-flow     # 按份额历史逐日回填 mart.etf_flow_daily（约 10 分钟，仅每周跑）
etf backfill-pulse    # 逐日回放三层状态，写满 250 个交易日
```

三条纪律：

1. **不偷看未来**：每天只用截至当天的事实（两融前缀、成交额前缀、截至当天的收盘价）；
2. **缺数据写 UNKNOWN**：宽基 ETF 层在申赎历史回填之前（2026-07-20 前）没有数据，
   整行如实显示"数据不足"，不拿两层数据假装三层；
3. **回放 ≠ 当时的快照**：回放行是"用今天存下的事实按同一条规则重算"，
   如果上游后来修正过历史事实，回放结果会与当日所见不同——界面上明确标注。

另一个已知近似：**篮子成员按当前口径回放**，成员变动未回溯（`etf_index_map` 有
`valid_from`，但历史篮子权重不值得在这个阶段引入）。

## 4. 架构落位

### 4.1 新增 Source Capability（按能力拆，不按网站堆类）

```text
MarketTurnoverSource   # 交易所每日概况（成交额/换手率/流通市值）
      ├── sse/market_turnover.py   上交所每日概况

      └── akshare/activity.py
```

业务层（`jobs/`、`services/`、`research/`）只能通过 `sources/registry.py` 拿适配器。

### 4.2 数据流水线

```text
Fetch（适配器）
  → Raw Snapshot（data/raw/source=*/dataset=market_*）
  → Normalize（统一单位：元；缺失 NULL）
  → Upsert Core（core.market_* / core.index_quote_daily）
  → Compute Mart（mart.market_pulse_daily / mart.index_position_daily）
  → WatchboardService
  → CLI / REST / Web 看盘台
```

全部同步幂等，按 `trade_date` upsert。

### 9.2 过程中发现并修掉的问题

**上游卡死导致同步挂起**：回补到第 7~19 个交易日时进程 0% CPU 卡住不动，
`lsof` 显示一条 ESTABLISHED 的 https 连接、上游不返回。

根因：项目原有的 `socket_timeout` 依赖 `socket.setdefaulttimeout`，
而它**只约束新建的 socket**；`requests` 连接池会把超时上下文之外建立的
连接复用进来，这类连接上的阻塞读永远不会超时。这不是看盘台独有的问题，
所有逐标的回补任务都受影响。

修复：`ingestion/retry.py` 新增 `call_with_deadline`（守护线程 + `join(timeout)`），
看盘台四条链路全部包上"硬超时 + 有界重试"，超时按既有约定记
`ops.quality_issue` 并继续下一条。已补 5 条单测锁定该行为。

**同一指数两套代码导致篮子漏数**：中证 500 在本项目的指数目录里同时存在
`000905`（中证口径）与 `399905`（新浪口径），实测南方中证 500ETF 映射到的是
`399905`，只按单一代码取篮子会把它整只漏掉（篮子从 13 只变 19 只）。

修复：`BROAD_BASE_INDEX_ALIASES` 按**指数身份**取并集（别名 → 主代码），
并补一条集成测试（同一指数两种口径都必须进篮子）。

**图例承诺了没画出来的线**：成交额图图例写着"橙线为 20 日均额"，但接口没返回
该字段，线根本没画（浏览器实测 `svg path` 数量为 0 才发现）。

修复：由服务层用 `research.rolling_mean` 补 20 日均额（前 19 个点窗口不足保持
NULL），并补集成测试锁定"前 19 个点为 NULL、之后有值"。

**折溢价单位与符号混用**：上游 `premium_discount_pct` 是"基金折价率"——
单位是百分比、且正负号与溢价相反（正 = 折价）。原先写的
`COALESCE(normalized, raw)` 会把折价显示成溢价。

修复：只取 `premium_discount_pct_normalized`（正 = 溢价），缺失即 NULL，
并补单测（0.0015 显示为 +0.15%，不取符号相反的 0.55）。

**前端两处自己挖的坑**：① `const cls = ... cls(...)` 自引用导致整页白屏（TDZ），
浏览器实测才暴露；② 篮子表把"折溢价（比例）"和"涨跌幅（百分数）"共用同一个
格式化函数，涨跌幅显示成 -169.00%。

修复：前者改名，后者按单位分开格式化；并新增**前端渲染回归测试**
（Node 跑真实 JS + 桩 DOM，校验不出现 undefined/NaN、单位渲染正确、
关键容器都有内容），缺少 Node 时自动跳过。

**量的单位又混了一次**：新发基金的单位是**亿元**、成交额是**元**。
前端一开始共用金额格式化函数，若直接复用会把 `1237.26 亿` 显示成 `1237 万`。

修复：新增 `yi_yuan`（亿元）格式分支，并在前端回归测试里同时断言
"1237.3 亿"与"-64.63%"出现——单位问题一律用测试钉死，不靠肉眼。

**mart 里的"周六数据"**：新鲜度面板显示"申赎估算 as-of 2026-09-12（周六）"，
追查到 `compute_mart` 直接用份额表的最新日期当指标日期，而份额快照历史上
被写入过周六日期（项目已知事故），于是派生出一条周六的申赎记录并长期留在 mart。

修复：`compute_mart` 增加交易日守卫——剔除不在交易日历里的观测（**留痕**到
`ops.quality_issue`，不是静默丢弃），保留合法历史继续计算；同时清理了已有
1262 条脏行（692 条非交易日 + 570 条没有对应份额事实的孤儿行，
`mart.etf_flow_daily` 2845 → 1583）。补了端到端测试。
