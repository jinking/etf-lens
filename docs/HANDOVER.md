## 1. 这次交付解决了什么

输入是一份《看盘三件套》方法论：**流动性（有没有钱）→ 量能（钱动没动）→ 宽基 ETF（大钱进没进）**。
项目原有的底座只有"ETF 层"（份额、净值、行情、持仓），第一、二层需要的市场数据**一条都没有**。

这次把三层框架完整落地成一个本地看盘台，并补上了执行纪律：

```text
数据层   市场层 4 类数据源接入 + 宽基指数长历史 + 申赎历史逐日回放
规则层   pulse_v1 → pulse_v2（确认机制），11 条自检规则
展示层   看盘台页面：三层状态 / 热力图 / 事件列表 / 五张图 / 篮子明细
交付层   etf pulse / etf audit / 每日与每周调度脚本 / MCP 工具
```

## 4. 规则引擎：pulse_v1 → pulse_v2

把历史回放出来做热力图时发现**状态机抖得太厉害**：

```text
            v1 切换次数/250 天   平均持续    v2 切换次数
流动性            30 次          8.1 天       21
量能              77 次          3.2 天       35      ← v1 是噪音
宽基 ETF          10 次         22.7 天        5
综合结论          69 次          3.6 天       36      ← 3.6 天变一次，谈不上"状态"
```

修法不是放宽阈值（治标），而是加**确认机制**：某层的原始信号必须连续
`CONFIRM_DAYS = 2` 个交易日落在新状态才真的切过去，代价是滞后 1 天。

原始信号与确认状态**都落库**：两者不一致的那一天，就是文档最看重的
"**边际变化刚出现、还没被确认**"，界面上单独标记。

## 6. 命令行

```bash
# 一次性建立市场层
etf sync-market --backfill-days 250    # 成交额回补 250 个交易日（约 10 分钟）
etf backfill-index-history --years 6   # 宽基指数长历史

# 看盘
etf pulse                              # 打印三层状态（同时写 mart）
etf api                                # 起服务，浏览器打开 /watchboard

# 历史回放（热力图与事件列表的前置）
etf backfill-flow                      # 申赎历史逐日回放（约 10 分钟，每周跑）
etf backfill-pulse --days 250          # 三层状态逐日回放

# 自检
etf audit [--json] [--strict]          # 架构约束 + 数据不变量

# 调度
scripts/run_daily.sh                   # 每日链路（末尾自动跑自检）
scripts/run_weekly.sh                  # 每周回补（净值/指数映射/指数长历史/成交额/申赎历史/状态回放）
```

## 7. 自检：把纪律变成可执行检查

见 `docs/AUDIT.md`。11 条规则（架构 3 + 数据 8），有 ERROR 时 `etf audit` 以非 0 退出，
并已挂在每日链路末尾。

第一次在真实库上运行就抓到一条**有实际后果**的问题：

```text
✘ [ERROR] core.etf_share_daily: shares 有 7 行 <= 0
```

`560650.SH` 的份额在 2026-08-21 起被上游写成 0 并持续 7 个交易日，派生出一条
`share_change_1d = -7,919,200` 的假巨额赎回。修法：validator 收紧为拒绝 `≤ 0`
（拦下 + 记 issue）、清理无效事实与派生行、补测试。

## 8. 口径纪律（不可破坏）

1. **单位**：成交额/市值为**元**；新发基金募集份额为**亿元**；折溢价是**比例**（0.0015 = +0.15%）；
   涨跌幅是**百分数**（-1.69 = -1.69%）；换手率是**水平值**（不加正负号）。三者不共用格式化函数。
2. **缺失即 NULL**：不用 0 顶替；月度聚合、累积曲线里缺失日**既不补 0 也不插值**。
3. **口径写进表**：成交额口径是"沪深两市股票"，不含北交所/基金/债券——字段名与界面都写明，不简称"全市场"。
4. **回放 ≠ 当时的快照**：历史状态是"用今天存下的事实按同一条规则重算"，上游若修正过历史，结果会与当日所见不同。
5. **原始 vs 确认**：`*_raw_state` 是当日原始信号，`*_state` 是确认状态，两者都落库。
6. **估算值**：一律带 `is_estimated = true` 与 `calculation_version`。

## 9. 已知缺口（如实记录，不用近似顶替）

| 缺口 | 原因 | 影响 / 何时消解 |
| --- | --- | --- |
| 深市 ETF 无日度份额变化 | 深交所只有当天快照，历史只能逐日积累 | 篮子净申购曲线里深市成员覆盖率低；跑满每日链路后自动补齐 |
| 折溢价历史只有快照起点 | IOPV 只在东财快照里有，历史回补源没有该字段 | 折溢价只展示最新一天 |
| 北向资金 | 上游 2024 年后停止披露 | 第一层少一个信号，界面已标注 |
| 深市换手率 | 深交所每日统计不披露 | `szse_turnover_rate_pct = NULL` |
| 创业板指/科创50 估值分位 | 上游没有这两条的 PE 序列 | 如实标注"暂不画线" |
| 沪深300 历史行情只有 50 只 | 历史回补受限于 `backfill-history` 的 top-n | 逐日全市场快照会补齐 |
| raw 快照会被同名覆盖 | `raw_store` 一个日期一个文件 | 长历史以 core 为准；raw 仅作当日排查 |

## 10. 测试与验证

```text
pytest                236 项全绿
ruff check src tests  干净
每日链路              scripts/run_daily.sh 端到端实跑通过（末尾自检 PASS）
真实库自检            ERROR 0 / WARN 0
浏览器验证            页面渲染 + 全部交互（窗口切换 / 排序 / 筛选 / 下钻 / 悬停）
```

值得保留的测试约定：

* **前端渲染回归**（Node 跑真实 JS + 桩 DOM）：单位渲染、无 `undefined/NaN`、关键容器非空——
  它抓到过两次真实前端 bug（TDZ 白屏、涨跌幅被当成比例显示成 -169%）；
* **每条自检规则必须能被触发**：先造违规数据确认抓到，再验证干净数据不误报；
* **单步确认与整段重放一致**：日更的 `step_confirmed` 必须与 `confirm_sequences` 结果逐条相同。

## 11. 下一步（按性价比排序）

1. **每日链路跑满**：深市份额/折溢价/状态历史都靠逐日积累，跑几周后第三层覆盖率会显著改善；
2. **`--confirm-days` 参数化**：让 1/2/3 天确认窗口的结论差异可比（纯回放，不动事实）；
3. **覆盖度断言**：把"界面每个数字都能追到 source + as-of""篮子覆盖率不得倒退"做成回归；
4. **复权净值字段**：公司行为（份额折算）已能识别并拒绝污染窗口，但复权净值需要独立采集；
5. **量能分位 3 年 / 5 年窗口**。
